How it was built

Two Claude Code sessions

SESSION 1

Game plan

Rules, server, UI, wiring and deploys.

THE CONTRACT

window.ASSETS

Keys agreed up front. Every addition announced by message.

SESSION 2

Assets

Sprites, sounds, music, effects, menu and takeover screens.

Each session owned its files. New work shipped as drop-in modules with a one-line hookup.

Two Claude Code sessions worked in parallel and talked through cross-session messages. One owned the game: rules, server, UI and deploys. The other owned everything you see and hear. The glue was one global object, window.ASSETS, with its keys agreed first. When the asset side needed to touch the menu or the takeover screen, it shipped a separate file, menu-bg.js or takeover-fx.js, plus a one-line hookup for the game side to add.
